# Демонстрация и подготовка к защите

## Показ приложения за 3–5 минут

1. Откройте галерею: фотографии приходят из Unsplash по 30 за запрос.
2. Прокрутите к концу: следующая страница дополняет список.
3. Откройте фото, покажите описание, свайпы и поворот экрана.
4. Нажмите сердечко и перейдите в избранное: состояние синхронизировано.
5. Остановите и снова запустите приложение без удаления: избранное сохранилось.
6. Удалите фото из избранного: сердечко в галерее стало пустым.
7. Покажите Test Navigator и результаты тестов. Объясните один тест ошибки и повтора страницы.

Не показывайте содержимое Secrets.plist на записи экрана или в публичной демонстрации.

## Объяснение своими словами

«Я использую UIKit для интерфейса и MVVM + Coordinator для разделения ответственности.
ViewModel хранит состояние и управляет загрузкой, ViewController отображает его,
а Coordinator создаёт экраны и выполняет переходы. URLSession получает данные через
async/await. Избранное хранится локально через Core Data и общее хранилище состояния,
поэтому сердечки согласованы на всех экранах».

## Что стоит уметь показать в коде

- AppCoordinator.start: создание вкладок и передача одного FavouritesStore всем ViewModel.
- GalleryViewModel.load: isLoading до await; увеличение номера страницы только после успеха.
- PhotoCell.loadImage: проверка отмены и id, защищающая переиспользуемую ячейку от старого ответа.
- ImageLoader.image: кеш и объединение одновременных запросов одного URL.
- FavouritesStore.toggle: сначала save, затем изменение состояния; ошибка оставляет прежние данные.
- FavouritesRepository: схема, fetch, save и rollback в Core Data.
- GalleryPaginationTests.failedPageRetry: первая страница, ошибка второй, повтор именно второй страницы.

## Вопросы, которые полезно потренировать

**Почему UIViewController не означает MVC?** Он относится к View-слою: показывает данные
и передаёт действия. Загрузка, страницы и состояние вынесены в ViewModel, навигация — в Coordinator.

**Что даёт протокол сервиса?** ViewModel не зависит от конкретного сетевого клиента.
В тесте сервис можно заменить объектом, который возвращает нужный ответ или ошибку без интернета.

**Что делает await?** Приостанавливает задачу до результата. Он не гарантирует,
что весь следующий код исполнится на фоновом потоке.

**Почему данные избранного не исчезают?** Core Data сохраняет их в SQLite-файл внутри
контейнера приложения. При следующем запуске приложение читает этот файл.

**Зачем кеш, если есть Core Data?** Кеш ускоряет повторный показ картинок и может очищаться.
Core Data хранит пользовательский выбор и метаданные независимо от кеша изображений.

**Что будет без интернета?** Метаданные избранного останутся. Кешированная картинка может
отобразиться, а для отсутствующей картинки и сети будет доступен повтор загрузки.

**Почему не сохранять только id?** Сохранённые описание, автор и URL позволяют показать
избранное, даже если фото больше нет в текущей загруженной странице галереи.

**Что улучшить дальше?** Фоновый context и порционная выборка для большого избранного,
расширение доступности, профилирование Instruments на устройстве, серверная защита ключа.
Эти улучшения не стоит выдавать за уже реализованные.
